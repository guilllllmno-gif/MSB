一、这页是干什么的

风控规则的两难：调严了误伤好客户（误报↑、SLA↑），调松了漏掉真风险（漏报↑）。直接改线上规则要等几周才知道好坏，代价是真金白银 + 客诉。

回测模拟让你改完先在历史数据上模拟——量化看清「收益 vs 代价」，达标再发布。它在规则闭环里的位置：

规则编辑器(改规则) → 回测模拟(发布前·历史验证) → 上线 → 规则效果/误报反馈(上线后·回溯) → 反哺再改

二、怎么打开

方式说明
走后端（推荐）终端执行 npm start（即 node server/server.js），浏览器开 http://localhost:3000/rc-backtest.html。计算走真实后端引擎，页面右上角标「后端引擎」。
直接打开文件双击 rc-backtest.html（file://）。后端不可达时自动回退到浏览器内同算法计算，标「本地回退」，结果一致。
从规则详情进入规则详情页点「回测模拟」按钮，带 ?id=RULE-xxx 深链，直接预选该规则并出结果。

三、操作流程

  1. 选规则：顶部「回测设置」→ 规则下拉。未选时停在落地页（含 6 个快捷入口按钮，点一下即开始）。
  2. 选回放窗口：近 30 日 / 近 90 日 / 2026 Q1。窗口越长，命中样本越多。
  3. 选对比基线：
    • 当前线上规则 v1：跟现有线上规则比，看新规则相对变化。
    • 无规则（全放行）：假设没有任何规则，看这条规则净增的拦截。
  4. 运行：点「运行回测」（或换规则即时重跑）。
  5. 看结果：页面分三块（下面逐块讲）。
  6. 调阈值：在「阈值扫描」拖动滑块或直接在曲线上拖动，找到满意的阈值；可一键「应用」推荐阈值。

四、三大区块逐块解读

页面顶部有蓝色「怎么读这页」引导条，对应下面三块：

① 回测概览 「上线后大概什么样」

口径
基于该规则的线上统计，是「当前阈值下的一个战绩点」。

4 个核心指标（KPI）

指标含义怎么算（原型）
回放交易本次回放覆盖的历史交易笔数该规则适用范围的交易池 × 窗口系数（近30日×1、近90日×3）
命中笔数规则命中多少笔；下方「vs 基线 +N」是相对基线的增减规则近30日命中 × 窗口系数
拦截金额命中交易涉及总额（标签随命中动作变化：拦截/暂缓/仅记录）命中笔数 × 该范围平均客单
预估误报率命中里预计有多少是误伤；下方标「偏高/健康区间」取自规则的误报率字段

每日命中分布（左下图）

  • 横轴：真实日历日期（按今天与回放窗口反推；近90日则每柱代表 3 天）。
  • 纵轴：当日/当段命中笔数，左侧有数量刻度与网格线。
  • 颜色：浅蓝 = 命中正确，红色 = 预估误报（按误报率拆分每根柱）。
  • 悬浮任意柱：显示「日期 · 命中 X（误报 Y / 正确 Z）」。
⚠ 注意
逐日柱高是把真实总命中数有机地铺到真实日期上的模拟形态；日期与总量是真的。

基线对比（右下卡片） —— 新规则 vs 基线，一眼看「收益 vs 代价」

项含义
命中量 8 → 9基线命中 → 新规则命中，右侧百分比为增幅
拦截真风险 +1比基线多识别出的真实风险笔数（收益）
误报量 1 → 1基线误报 → 新规则误报（代价）

结论句自动判断：误报偏高→建议放宽阈值再回测；质量良好→可考虑发布

② 阈值扫描 「阈值该切在哪」

口径
在一份独立的模拟评分总体上做阈值实验（与①不同：①是线上单点，这里是扫描全阈值）。后端会标注样本量与真风险占比，如「在 4,000 笔模拟交易（约 3.9% 为真风险）上逐阈值计算混淆矩阵」；接入真实 CSV 时标「后端引擎 · 真实数据」。

命中阈值滑块：风险评分 ≥ 多少才算命中。可直接在下方曲线上拖动改阈值。

当前阈值下的 5 个指标

指标含义公式
命中量评分 ≥ 阈值的交易数TP + FP
误报率命中里有多少是误伤FP /（TP+FP）
精确率命中里有多少是真风险TP /（TP+FP）
召回率全部真风险里抓住了多少TP /（TP+FN）
漏报没抓到的真风险笔数FN

混淆矩阵（2×2） —— 把上面的「率」对上「数」

真值 · 真风险真值 · 正常
模型命中（≥阈值）TP 命中正确FP 误报
模型放行（<阈值）FN 漏报TN 正确放行

权衡曲线（图）

  • 横轴：阈值 0–100；左轴：命中量；右轴：比率 0–100%。
  • 三条线：蓝 = 命中量（带面积填充）、红 = 误报率、绿 = 召回率。
  • 紫色虚线：F1 最优阈值标记。
  • 读法：阈值往左 → 命中↑、召回↑、漏报↓，但误报↑、精确率↓；往右相反。
  • 交互：在图上拖动/悬浮即可改阈值，光标处弹出「阈值 X · 命中 · 误报% · 召回%」，下方矩阵与指标实时联动。

推荐阈值（曲线下方）

  • F1 最优阈值　精确率与召回率的平衡点（综合最优），点「应用」跳到该阈值。
  • 召回≥90% 下误报最低　要求几乎不漏（召回≥90%）时误报最低的阈值——适合高风险、宁可错杀的规则。

③ 命中核验 「凭什么说它误报」

逐单对照历史人工结论，核验每条命中到底是真风险还是误报。

列含义
订单 / 告警命中的交易标识
商户交易主体
金额交易金额
命中评分该笔在本规则下的风险评分（误报多落在阈值边缘的中分，命中正确多为高分）
模型判定规则给出的处置动作（暂缓/冻结/拒绝…）
历史人工结论当时分析师/案件的最终结论（放行/驳回/补材料…）
是否误报模型判定 vs 人工结论对照：含「放行」判为误报，否则命中正确

五、数据来源与真实化

来源标签（阈值扫描卡右上）：

  • 后端引擎　走 Node 后端的模拟总体计算；
  • 后端引擎 · 真实数据　后端读到了真实 CSV；
  • 本地回退　后端不可达，浏览器内同算法计算。

接入真实数据（零改码）：把带标注的历史交易放到 server/data/<ruleId>.csv：

score,label
92,1      # score=该笔在本规则下的风险评分(0-100)；label=人工真值 1风险/0正常
14,0

文件存在即自动改用真实数据，页面来源标签变为「真实数据」。

原型边界
未放 CSV 时，数据是确定性模拟（同一规则永远同一结果，可复现；误报率越高的规则，正常样本评分被抬得越高、两类越难分）。①回测概览的金额/命中由规则线上统计推算，是演示口径。

六、常见决策场景

看到解读行动
误报率高（如 ≥35%）、放行多规则过度拦截、误伤正常客户调高阈值 / 加白名单豁免 / 下调权重，重新回测
召回低、漏报多规则太松、放过真风险调低阈值 / 叠加信号，重新回测
F1 最优阈值的误报仍很高规则本身区分度差（真假分布重叠）重构规则逻辑或叠加其他信号，而非只调阈值
基线对比：多拦真风险、误报与 SLA 变化小收益 > 代价可考虑发布

七、术语表

术语含义
TP（命中正确）模型命中且确实是真风险
FP（误报）模型命中但其实是正常交易（误伤）
FN（漏报）模型放行但其实是真风险（漏掉）
TN（正确放行）模型放行且确实正常
精确率 Precision= TP/(TP+FP)　命中里有多少是对的
召回率 Recall= TP/(TP+FN)　真风险里抓住了多少
误报率（本页口径）= FP/(TP+FP)　命中里有多少是误伤
F1精确率与召回率的调和平均，综合衡量
SLA处置时效；误报越多、人工复核压力越大、SLA 越长
