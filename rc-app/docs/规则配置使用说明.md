# 监控规则配置 · 使用说明

面向风控分析师 / 风控总管。讲清楚「一条规则怎么配、配完去哪、谁会跑到它」。
入口:左侧导航 **规则**(`/rules`)→ 右上角 **新建规则**;或在规则详情页点 **编辑规则**。

---

## 总览 · 风控流水线(一笔交易怎么流动)

一笔命中规则的交易,按生命周期在各模块间**串行流转**,任一时刻只属于一个环节:

```
事中监控 →(转研判)→ 告警研判 →(升级/建案)→ 案件管理 →(起草 STR)→ 报告报送 →(结案)→ 处置记录
实时闸口          深度调查            合规案件             STR · FINTRAC          全口径归档
```

- **旁路汇入**:**事后监控**(批量回溯)/ **关联团伙**(团伙识别)不走事中环节,**直连 告警研判 / 案件管理**(钱已动;资金已出账则走资金追溯)。
- **反馈闭环**:事后确认的可疑 typology **规则回填 → 监控规则 → 回到事中实时拦截**同类,堵下一笔。
- 不是每笔都走完:事中能当场放行 / 拒绝的,直接进处置记录。

> 这张流转图原先挂在仪表盘顶部 —— 教学 / 说明类内容不在操作页占位,收到使用说明这里。

---

## 0. 先理解两件事

### 0.1 规则有生命周期,新建不直接上线
```
新建/回填 → 回测中 →(回测达标·提交审批)→ 待审批 →(总管审批)→ 已上线·生效
                                                              ├→ 已驳回
                                                              └→ 已停用(可重新启用)
```
- **新建的规则一律先进「回测中」**,不会立刻拦真实交易。
- 回测命中 / 误报达标后**提交审批**,由**风控总管**批准才上线生效。
- **改一条已上线的规则**:不直接动线上,而是提交一份**拟议变更**,总管审批通过后才切换(原版在审批期间照常生效)。
- **名单筛查类硬规则**(制裁 / 法定命中即拦)编辑被锁定,灵敏度调整走名单管理。

### 0.2 规则有两种「命中后做什么」
- **仅评分**:命中只给交易**加风险分**(权重),自己不处置。最终怎么处置由**全局策略**按总分裁决(见第 6 节)。
- **生成告警**:命中生成告警并执行你配的**处置动作**。

> 多条规则会一起跑同一笔交易。跨规则的处置取 **「最严生效」**(拒绝 > 冻结 > 补料 > 转人工 > 放行),不取最宽松。

### 0.3 权重校准闭环(规则不是拍一次定死)
规则 / 权重经一个持续收敛的闭环,不是配完就一劳永逸:

```
建模·提案 → 回测(历史验证) → 审批上线 → 事中生效·盯误报 → 事后确认·回填
   ↑                                                              │
   └──────────────── 误报偏高 / 事后成案 → 回「建模」调权重,重走一圈 ──────────┘
```

- 上线不是终点:**盯误报率**,偏高就回去调阈值 / 权重。
- **事后监控**确认的成案 / 误报,**回填**成规则草案、再校准。
- **制裁 / 名单类硬规则不在此环**(命中即拦,不靠权重与阈值)。

## 1. 命名与描述
弹窗顶部:
- **规则名称**(必填):一句话说清抓什么,如「滑窗结构化拆分」。
- **规则描述**(选填):补充意图 / 适用背景。

## 2. 左栏「触发条件」

### 2.1 头部:执行场景
右上角下拉选**执行场景**,决定规则能不能实时拦:
| 场景 | 含义 |
|---|---|
| **事中 · 实时闸口** | 交易发生时即可判定(单笔阈值 / 名单 / 地址 / 同主体滑窗),可当场放行/拒绝 |
| **事后 · 批量回溯** | 需跨时间/跨主体聚合(扇入 / 速度 / 集中度 / 链跳),只能批量回扫 |
| **事中 + 事后** | 事中近实时标记 + 事后复扫补全 |

选了**规则类别**后系统会按类别**自动建议**场景(没手动改过时)。

### 2.2 规则元数据
- **规则类别**:金额阈值 / 链上溯源 / 行为模式 / 名单筛查 / 评分模型 / 统计聚合。
- **适用业务线**:限定这条规则只在哪类交易上跑(充值 / 提现 / 兑换 / on-ramp / off-ramp / 全部)。
> 不再单独填「适用网络」—— 链适用性要么与规则无关(默认 BTC/ERC/TRC 全跑),要么由规则类别 / 条件逻辑隐含(如「链上溯源」类、「跨链 / 隐私币」条件)。
- **适用对象**(选填,多选):定向到哪类商户 —— 见第 5 节。**不选 = 全部商户都跑。**

### 2.3 条件构造器(核心)
一条规则 = **若干子句**,子句之间用 **AND(且)/ OR(或)** 连接;还可拆成**子组**做一层嵌套。

**每条子句 = 字段 + 运算符 + 值**,外加两个可选维度:

#### ① 滑动窗口(窗口型指标必填)
选到**滑窗累计金额 / 滑窗笔数 / 对手集中度 / 扇入主体数**这类「跨时间聚合」指标时,会出现**滑动窗口**选择(1 小时 / 24 小时 / 48 小时 / 7 天 / 14 天 / 30 天 / **自定义**)。
> 例:`48 小时内 滑窗累计金额 ≥ $9,000`(抓规避 LVCTR 的拆分)。

#### ② 比较基准(数值字段可选)
不只跟固定数比,还能跟「相对参照」比:
| 基准 | 含义 | 抓什么 |
|---|---|---|
| **绝对值** | 跟固定/法定阈值比 | LVCTR 大额、Travel Rule、评分超阈 |
| **× 自身历史基线** | 倍于该主体自己的常态 | 休眠突发、账户接管(VIP 高基线不误报、新户低基线即触发) |
| **同业群百分位 P** | 高于同业商户群的 P 分位 | 速度/峰值偏离、无历史可比的新户 |
| **偏离均值 σ** | 偏离自身均值 N 个标准差 | 做市/促销等高波动账户的真异常 |
> 类别型字段(名单 / 地址标签 / 跨链 / KYB)只能「命中 / 包含」,没有比较基准。

#### ③ 分层阈值(数值 + 绝对值基准时可勾)
勾「按 KYC 等级 / 业务线 / 注册地分档取阈值」后,一条子句可配多档:
> 例:`单笔金额 ≥ 按 KYC 等级分档(VIP:50,000 / 新户:5,000 / 默认:10,000)`,避免为不同分群写一堆近重复规则。

#### 添加条件 vs 添加子组(常被问)
- **添加条件** = 在**当前组里**再加一条判断;组内所有条件用**同一个 AND/OR** 连。
- **添加子组** = 新开**一整组**(有自己的内部 AND/OR),**组与组之间**再用另一个 AND/OR 连 —— 用来表达「AND 和 OR 混用」的括号逻辑:
> `(单笔 ≥$9k 且 账户<30天) 或 (24h 笔数 ≥5 且 集中度 ≥80%)`
>
> 这种「一条规则覆盖两条独立可疑路径」,平铺一层的 AND/OR 表达不出来,才需要子组。

**口诀**:条件**都用「且」或都用「或」→ 只加条件**;需要 **(…且…) 或 (…且…)** 这种混着用 → **才加子组**。

底部**常驻句子条**实时把你配的条件翻译成一句话,随时可看。

## 3. 右栏「命中动作」

### 3.1 事件操作
- **仅评分 / 生成告警**(二选一,见 0.2)。仅评分 = **永久**只加分(由全局策略裁决);≠「上线策略 · 影子模式」的**临时**评估。
- **停止扫描**:勾上后命中即止(first-match),本规则处置**直接生效、不再与后续规则比「最严生效」** —— 多用于制裁 / 硬拦截。默认关闭 = 继续扫描、跨规则取最严。

### 3.2 处置动作(生成告警模式)
分两层:
- **终态处置(单选,互斥)** —— 一笔交易只能落一个最终状态,按严格度排列:
  > 拒绝交易 > 冻结资金 > 要求补充材料 > 智能入账(转人工审核) > 放行 · 仅记录
- **附带动作(多选,选填)** —— 叠加在终态之上的工作流副作用,可多勾:
  > 升级 MLRO · 通知合规官 · 加入观察名单 · 生成案件 · 触发 EDD 复核

**阶梯处置**(可勾):终态按**金额 / 风险分**区间分档触发:
> `≥$9,000 → 转人工审核`、`≥$50,000 → 冻结资金`(自高到低匹配,命中最高满足档)。

### 3.3 风险权重
0–100,命中后累加到交易风险分。**仅评分模式必填**;生成告警 + 终态处置时为**选填**(只作评分聚合参考)。权重越高越易把总分推过拦截线。

### 3.4 上线策略(进阶 · 默认折叠)
- **影子模式**:命中只告警不处置,跑一段确认误报率再切实拦。
- **灰度比例**(10–100%):先小流量试跑再全量。
- **到期日**:到点自动失效(临时加严用,如某交易所被盗/新制裁)。
> 改已上线规则的上线策略,同样要走总管审批。

## 4. 配完怎么验 / 提交

两个测试工具,各司其职:
- **单笔回放测试**(左栏按钮 → **弹窗** · **验逻辑**):选一笔真实历史样本交易 → **回放** → 看**命不命中**、逐子句 ✓/✗、不命中**卡在哪条**、命中后**取哪个处置**。调规则不再靠猜。
- **运行 30 天回测**(页脚 · **估影响**):底部弹结果卡 —— 扫描量 / 命中 / 误报率 / 命中有效率 / 升级转案 + 近 30 日命中柱状 + **达标判定**(达标可提交审批 / 误报偏高建议调阈值)。
- **创建规则**:落「回测中」。**保存修改 / 提交变更审批**:已上线规则走审批,其余直改。

---

## 5. 适用对象:谁会跑到这条规则

并非所有商户都跑所有规则。**适用对象**多选把规则定向到商户分群:
- **派生型群组**(系统实时算,不靠打标签):高风险商户(风险分≥80)/ 新户·KYB 未完成 / 高风险辖区 / 白名单除外。
- **业务模式标签**(靠分类/识别):OTC·交易所类 / 加密 ATM 运营商 / DeFi·跨链协议类。

> **不选 = 全部商户都跑。法定核心(制裁筛查 / LVCTR)对所有商户恒生效,不受适用对象限制。**

想看一个商户实际跑哪些规则:商户 360 档案(`/entity?name=…`)的**「适用规则」卡**(法定核心 / 定向命中 / 不适用 三桶),以及它的**业务模式标签**(模型自动识别 → 人工确认)。

---

## 6. 评分模式的处置在哪定

「仅评分」规则只加分,最终处置在 **全局策略**(`/strategy`)的**风险分处置矩阵**按总分裁决:
| 风险分 | 处置 |
|---|---|
| ≥ 80 | 拦截 + 强制人工复核 |
| 60–79 | 放行 + 转告警研判 + 留痕 |
| 40–59 | 放行 + 留痕(抽样复核) |
| < 40 | 直接放行 |

跨规则仲裁、名单优先级、数据缺失兜底等也都在全局策略页。

## 7. 常见场景配方(Cookbook)

| 想抓什么 | 怎么配 |
|---|---|
| **结构化拆分(规避 LVCTR)** | `滑窗累计金额 ≥ $9,000`(窗口 48h)**且** `滑窗笔数 ≥ 5`(窗口 48h) |
| **大额单笔(LVCTR)** | `单笔金额 ≥ $10,000`(绝对值) |
| **休眠后突发** | `账户休眠天数 ≥ 60` **且** `滑窗笔数 ≥ 自身历史基线 ×5`(窗口 24h) |
| **速度/峰值偏离** | `滑窗笔数 > 同业群 P95`(窗口 24h) |
| **多账户扇入归集** | `扇入主体数 ≥ 4`(窗口 14 天) |
| **混币器/跨链** | `跨链 / 隐私币 命中 隐私币 / 跨链桥`(类别型,无窗口/基准) |
| **VIP 与新户不同阈值** | `单笔金额 ≥ 绝对值`,勾**分层阈值**按 KYC 分档 |
| **同一规则金额越大处置越狠** | 勾**阶梯处置**:`≥$9k 转人工 / ≥$50k 冻结资金`,再勾**附带动作**「升级 MLRO」 |

---

## 8. 一句话速记
> **条件**(字段 + 窗口 + 基准 + 值,可嵌套子组、可分层)→ **动作**(评分加权 / 终态单选 + 附带多选,或阶梯;可影子 · 灰度 · 到期)→ **定向**(适用对象,默认全部)→ **回放验逻辑 + 回测估影响** → **审批 → 上线**。
