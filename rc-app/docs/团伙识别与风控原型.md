## 一、技术与视觉
- React + `@heroui/react` v2 + Tailwind v4 + Vite。
- 字体：Golos Text（`src/assets/fonts/GolosText-VariableFont_wght.ttf`，经 `--font-sans` 全局生效）。ID 文本用 Golos（非等宽），仅钱包地址 / 交易哈希保留 `font-mono`。
- 布局：灰色侧边栏（可收起，宽度过渡动画）+ **白色内容区（无圆角包裹、无滚动条）**；深色模式用 HeroUI 原生主题（深色边框用半透明白，避免黑线）。
- 圆角层级：容器 16（`.card`）/ 控件 12 / 小标签 8 / 徽章 6 / 胶囊 full。
- 路由级代码分割（`React.lazy`）。
- 提交后自动 commit + push 到 origin（见全局记忆 auto-push）。push 偶发 SSL 失败，需 `dangerouslyDisableSandbox` 重试。

## 三、关联团伙模块（本期重点，已完成）
数据：`lib/rings.ts`；状态/owner：`lib/store.ts` 的 `ringStore`（内存，刷新重置，无后端）。

### 识别原理（设计哲学）
共享标识连成**加权边** → 剔除超级节点 → 累积强度过阈值 → 图聚类成团 → 多维叠加打分。
- **区分度加权**：资金 40 > 地址 30 > 设备 20 > IP 10（资金/地址难伪造，IP/设备易巧合）。
- **阈值 60%**：置信度 ≥ 60% 才成团（待认领）；< 60% 仅「观察中」。
- **超级节点剔除**：交易所热钱包 / 公共 IP 等高频公共节点降权，避免聚类坍缩。
- **置信度 = 各维度 contrib 之和**（堆叠条可视化；数据里 confidence 必须等于 shared.contrib 之和）。
- 同质地址收敛成「×N 簇」节点，保持图谱节点数可控。

### 生命周期状态机（`RING_STATES` + `ringActions` 门控）
`待认领(pending)` →(认领)→ `调查中(investigating)` →(处置)→ 终态；`观察中(watching)` 为弱关联旁路。
- 动作门控（`ringActions`）：**待认领=只能认领**；**观察中=只能升级/标记误报**（不能聚案/列名单，尊重阈值）；**调查中=全开放**；终态=无动作。列表的「并入案件」快捷键也受门控。
- 处置动作→状态（`DISP_STATE`）：并入案件→已聚案、批量列名单→已列名单、升级MLRO→已升级、标记误报→已关闭·误报、要求补充材料→保持调查中（非终态）。

### 页面
- `pages/RingList.tsx`：状态 tiles + 搜索 + 经手人/SLA 列 + 行操作 + **新建团伙**（`components/NewRingDrawer.tsx`，选成员+维度→自动折算置信度）。
- `pages/RingDetail.tsx`：自适应放射状**关系图谱**（节点随数量缩放；边色=维度、粗细=强度、标签=强度）+ **共享证据明细**（合并在图谱卡内，每条连线=主体对）+ **置信度构成**（堆叠条 + 阈值标记 + 维度行可展开看命中连线）+ 团伙成员 + **研判处置抽屉**（处置结论/流程操作 + 表单 + **操作后影响**文案）。
- `components/RingBasis.tsx`：「识别依据」气泡（通用流水线 + 本团伙要点）。

### 术语约定（统一过）
- **连线（主体对）** = 图上的边（edge）；曾混用「关系/关联边」，已统一为「连线」。
- **项（证据）** = 一条连线上共享的具体实例数（一对主体可多项）。
- **强度** = 单条连线的关联强度；**置信度** = 团伙整体累计分。
