0先理解两件事

① 规则有生命周期,新建不直接上线

新建 / 回测中→ 待审批→ 已上线 · 生效 分支:已驳回　已停用(可重新启用)
  • 新建规则一律先进「回测中」,不会立刻拦真实交易。
  • 回测命中 / 误报达标后提交审批,由风控总管批准才上线。
  • 改一条已上线的规则:不直接动线上,而是提交拟议变更,总管审批通过才切换(原版审批期间照常生效)。
  • 名单筛查类硬规则(制裁 / 法定命中即拦)编辑被锁定,灵敏度走名单管理。

② 规则有两种「命中后做什么」

仅评分

命中只给交易加风险分(权重),自己不处置。最终处置由全局策略按总分裁决(见第 6 节)。

生成告警

命中生成告警并执行你配的处置动作(见 3.2)。

多条规则会一起跑同一笔交易。跨规则的处置取 「最严生效」:拒绝 > 冻结 > 补料 > 转人工 > 放行,不取最宽松。

1命名与描述

弹窗顶部:规则名称(必填,一句话说清抓什么,如「滑窗结构化拆分」)+ 规则描述(选填,补充意图 / 背景)。

2左栏 · 触发条件

2.1 执行场景(头部右上)

决定规则能不能实时拦。选好规则类别后系统会按类别自动建议场景。

场景含义
事中 · 实时闸口交易发生时即可判定(单笔阈值 / 名单 / 地址 / 同主体滑窗),可当场放行 / 拒绝
事后 · 批量回溯需跨时间 / 跨主体聚合(扇入 / 速度 / 集中度 / 链跳),只能批量回扫
事中 + 事后事中近实时标记 + 事后复扫补全

2.2 规则元数据

  • 规则类别:金额阈值 / 链上溯源 / 行为模式 / 名单筛查 / 评分模型 / 统计聚合。
  • 适用业务线:限定只在哪类交易上跑(充值 / 提现 / 兑换 / on-ramp / off-ramp / 全部)。链适用性不单独填 —— 要么与规则无关(默认 BTC/ERC/TRC 全跑),要么由类别 / 条件隐含。
  • 适用对象(选填,多选):定向到哪类商户 —— 见第 5 节。不选 = 全部商户都跑。

2.3 条件构造器(核心)

一条规则 = 若干子句,子句间用 AND(且)/ OR(或) 连接;还可拆成子组做一层嵌套。每条子句 = 字段 + 运算符 + 值,外加两个可选维度:

① 滑动窗口

窗口型指标(滑窗累计金额 / 滑窗笔数 / 对手集中度 / 扇入主体数)必配窗口:1h / 24h / 48h / 7d / 14d / 30d / 自定义。

② 比较基准

数值字段可选:绝对值 / × 自身历史基线 / 同业群百分位 P / 偏离均值 σ。类别字段(名单 / 标签 / 跨链 / KYB)无基准。

③ 分层阈值

数值 + 绝对值基准时可勾:按 KYC 等级 / 业务线 / 注册地分档取不同阈值。

比较基准含义抓什么
绝对值跟固定 / 法定阈值比LVCTR 大额、Travel Rule、评分超阈
× 自身历史基线倍于该主体自己的常态休眠突发、账户接管(VIP 不误报、新户即触发)
同业群百分位 P高于同业商户群 P 分位速度 / 峰值偏离、无历史可比的新户
偏离均值 σ偏离自身均值 N 个标准差做市 / 促销等高波动账户的真异常

添加条件 vs 添加子组(常被问)

  • 添加条件 = 在当前组里再加一条判断;组内所有条件用同一个 AND/OR 连。
  • 添加子组 = 新开一整组(有自己的内部 AND/OR),组与组之间再用另一个 AND/OR 连 —— 用来表达「AND 和 OR 混用」的括号逻辑:
( 单笔 ≥ $9k 且 账户 < 30天 ) 或 ( 24h 笔数 ≥ 5 且 集中度 ≥ 80% )

这种「一条规则覆盖两条独立可疑路径」,平铺一层的 AND/OR 表达不出来,才需要子组。

口诀:条件都用「且」或都用「或」→ 只加条件;需要 (…且…) 或 (…且…) 这种混着用 → 才加子组。

底部常驻句子条会把你配的条件实时翻译成一句话,随时可看。

3右栏 · 命中动作

3.1 事件操作

  • 仅评分 / 生成告警(二选一,见 0.2)。仅评分 = 永久只加分(全局策略裁决),≠「影子模式」的临时评估。
  • 停止扫描:勾上后命中即止(first-match),本规则处置直接生效、不再与后续规则比「最严生效」 —— 多用于制裁 / 硬拦截。默认关闭 = 继续扫描、跨规则取最严。

3.2 处置动作(生成告警模式)

分两层。终态处置(单选,互斥) —— 一笔交易只能落一个最终状态,按严格度排列:

拒绝交易› 冻结资金› 要求补充材料› 智能入账 · 转人工› 放行 · 仅记录

附带动作(多选,选填) —— 叠加在终态之上的工作流副作用,可多勾:

升级 MLRO通知合规官加入观察名单生成案件触发 EDD 复核

阶梯处置(可勾):终态按金额 / 风险分区间分档,自高到低匹配:

≥ $9,000 → 转人工审核　·　≥ $50,000 → 冻结资金

3.3 风险权重

0–100,命中后累加到交易风险分。仅评分模式必填;生成告警 + 终态处置时为选填(只作评分聚合参考)。权重越高越易把总分推过拦截线。

3.4 上线策略(进阶 · 默认折叠)

影子模式

命中只告警不处置,跑一段确认误报率再切实拦。

灰度比例

10–100%,先小流量试跑再全量。

到期日

到点自动失效(临时加严用,如某交易所被盗 / 新制裁)。

改已上线规则的上线策略,同样要走总管审批。

4配完怎么验 / 提交

两个测试工具,各司其职:

  • 单笔回放测试(左栏按钮 → 弹窗 · 验逻辑):选一笔真实历史样本交易 → 回放 → 看命不命中、逐子句 ✓/✗、不命中卡在哪条、命中后取哪个处置。
  • 运行 30 天回测(页脚 · 估影响):底部弹结果卡 —— 扫描量 / 命中 / 误报率 / 有效率 / 升级转案 + 近 30 日命中柱状 + 达标判定。
  • 创建规则:落「回测中」。保存修改 / 提交变更审批:已上线规则走审批,其余直改。

5适用对象 · 谁会跑到这条规则

并非所有商户都跑所有规则。「适用对象」多选把规则定向到商户分群:

派生型群组(系统实时算)

高风险商户(风险分 ≥80)/ 新户 · KYB 未完成 / 高风险辖区 / 白名单除外。不靠打标签。

业务模式标签(分类 / 识别)

OTC · 交易所类 / 加密 ATM 运营商 / DeFi · 跨链协议类。靠开户分类或模型自动识别。

不选 = 全部商户都跑。法定核心(制裁筛查 / LVCTR)对所有商户恒生效,不受适用对象限制。

想看一个商户实际跑哪些规则:商户 360 档案的「适用规则」卡(法定核心 / 定向命中 / 不适用 三桶)与它的业务模式标签(模型自动识别 → 人工确认)。

6评分模式的处置在哪定

「仅评分」规则只加分,最终处置在全局策略的风险分处置矩阵按总分裁决:

风险分档处置
≥ 80高危拦截 + 强制人工复核
60 – 79偏高放行 + 转告警研判 + 留痕
40 – 59中低放行 + 留痕(抽样复核)
< 40低直接放行

跨规则仲裁、名单优先级、数据缺失兜底也都在全局策略页。

7常见场景配方

想抓什么怎么配

8一句话速记

条件(字段 + 窗口 + 基准 + 值,可嵌套子组、可分层)→ 动作(评分加权 / 终态单选 + 附带多选,或阶梯;可影子 · 灰度 · 到期)→ 定向(适用对象,默认全部)→ 回放验逻辑 + 回测估影响 → 审批 → 上线。
